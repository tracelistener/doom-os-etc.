## Implementation and sound differences

The recipes are compiled as freestanding Thumb-2 C, hardware floating point,
no allocation or mutable global state. Sine/cosine use a 2,048-point linearly
interpolated lookup table. The scanned table is the same 32 × 256 Float32
frame data generated by Wave Lab. Grit reads the stock per-voice cycle random
value at offset `0x40`.

The SP's integer DUTY 0–100 indexes precomputed LP harmonic gains, Drive
parameters/normalization, Organ registrations, Vowel formants and CZ/Sync
ratios. Drive uses a 1,025-point tanh lookup; Vowel envelopes use a 257-point
fractional-exp2 lookup plus exact powers of two. No new recipe calls the stock
libm exp2 function. The raw cached recipe API quantizes DUTY to integer percent,
matching the physical control, rather than promising continuous off-grid parity.

LPSaw/LPSqr retain all 64 potential harmonics and the original note-dependent
cutoff. Their loop multiplies cached weights instead of computing three divides
per harmonic. LPSaw's 193 divides per voice-sample become one; LPSqr's 97
become one. Drive's five become zero. All 17 names/indices are preserved.

The release fix is part of this same wave build. Note-off retains the original
counter -200, and all-stop writes -200. The 400-sample stock release begins near
unity, not at half amplitude. Archived v4 sources and stock-only overlays remain
unchanged; leaving Wave Lab off still generates that older baseline.

The C module is 110,776 bytes, linked at `0x60334c00`. Bridges and padding make
its XIP section 111,808 bytes at `0x60334800`; the original image is padded by
1,008 bytes before appending it. No new RAM copy or zero-init row is added.
All 14 working-v4 scatter rows and both table-header words remain byte-exact.
The OS pool stays at `0x8353d82c`, exactly as in working v4, with no extra RAM
reservation. Existing DOOM flash offsets and unrelated bytes remain intact.

The new entry gateway sends stock/invalid types and the stock exporter entry
back to the unmodified v4 gate. Only valid new per-voice types enter the custom
C renderer. Stock oscillator body, prologue, level scaling, phase advancement,
envelope/fades and return path are unchanged. Sine lookup also wraps a value
rounded to exactly 1 before indexing; this possible edge case is not claimed
as the cause of the observed boot distortion.
TYPE, FREQ, DUTY, name/text/label and export-period guards are extended.
The displaced stock name TBH is reconstructed from its original table;
stock names are tested too. New unknown type values still fall silent.

The browser demo additionally applies RMS matching, a DC blocker and output
saturation. The firmware deliberately uses Roland's existing LEVEL/envelope
chain instead. Fixed headroom multipliers are 0.16 for LPSaw/LPSqr/Organ and
0.46 for Vowel; other types use unity, with a final ±1 bound before stock
LEVEL scaling. Therefore preview loudness is not identical to the demo.
The existing polyphony half gain still applies. Four loud voices can clip.
Only the additive harmonic banks/organ impose their recipe's Nyquist guard;
nonlinear and table types can alias on high notes, as in the source recipes.

CPU headroom has **not** been measured on hardware. In the four-voice 64-frame
fixture, LPSaw drops from 327,549 instructions/49,408 F32 divides in V2 to
126,077 instructions/256 divides in V3. LPSqr drops from 229,245/24,832 to
126,333/256. Drive drops from 138,537/1,280 to 63,529/0. These are work counts,
not clock cycles or proof of deadlines under sampler/effects/DOOM load.

## Reproduce and verify

Use the dependencies in `requirements.txt`, plus the pinned workspace-local
`ziglang==0.13.0` distribution (or an existing Zig 0.13.0 binary):

```sh
python -m pip install ziglang==0.13.0 --target .wave_toolchain
python synth/compile_waves.py --zig /path/to/zig
python synth/build.py /path/to/stock/SP404MKII_APP1.bin
python synth/patch_waves.py out/doom-poly-v4/SP404MKII_APP1.bin --out out/doom-poly-waves-v3-budget --web
```

If building from the fork directory, `.wave_toolchain` can be kept outside it
or is ignored by Git. On Windows the compiler is `.wave_toolchain/ziglang/zig.exe`.
The compile step generates ignored `build/waves-v3-budget/` lookup data, ELF, module,
symbols and source/tool provenance. The binary overlay in `waves-data.js`
is generated, not hand-edited. No complete Roland firmware is committed.

```powershell
$env:DOOM_STOCK_APP1 = 'C:\path\to\stock\SP404MKII_APP1.bin'
$env:DOOM_POLY_APP1 = 'C:\path\to\doom-poly-v4\SP404MKII_APP1.bin'
$env:WAVE_LAB_HTML = 'C:\path\to\sp404mk2-sound-generator\index.html'
python -m unittest discover -s synth -p 'test*.py'
node synth/test_browser.cjs $env:DOOM_STOCK_APP1
```

There are 88 integration tests: 40 previous composition/poly regressions and
48 on the wave image. The latter compare all 17 original JS formulas across
2,040 phase/DUTY/pitch cases, plus 16,968 cached-recipe cases covering every
integer DUTY 0–100 (maximum sampled absolute error <0.000012), run every new
type through the real oscillator, render four live voices, run held-chord
export through the real stock loop with simulated file I/O, check stock/new
labels and ranges, and execute the original real boot scatter copies. They now
also assert the unchanged boot table/pool/stock gate, corrected Noise labels,
stock -200 release counters and full release lifetimes, compare 192 stock-audio
blocks bit-for-bit with working v4 (12 types; stock 8-10 use VSEL unsupported
by this Unicorn setup), and exercise sequential real TYPE/fade transitions.
The page/applier tests verify all three outputs, dependencies, reset, padded
base64 lengths and corrupt-overlay refusal. These are not full device boot,
visual browser, SD-card or timing tests. Original workspace tests also remain
passing and the preceding images are not overwritten. Separate workspace
tests run 1,700 oscillator corner cases (sampled peak 487 instructions, at
most one divide, no libm exp2 calls), all 15 stock hold/release comparisons
against stock half gain, and all 17 new waves' near-unity release/idle output.
The block-work report has 252 hold/release/idle cases for this wave-enabled image.

## First hardware check

1. Verify backup and rollback files. Test ordinary sample playback.
2. BEFORE any new wave, test ONE stock Sine at modest LEVEL immediately after
   boot. If it distorts, STOP and roll back to v4; report that result.
3. Only if stock playback is clean, try ONE FM1:1 voice and sweep DUTY. Stop
   for crackles, unexpected loudness, stuck notes or a hang.
4. Test each new wave individually, then two and four voices. Sweep DUTY and
   TYPE while notes are held and releasing. Save LP banks/Drive/Organ/Vowel
   and simultaneous sampler/effects/DOOM activity for last.
5. Test held-pad LEDs, shared parameters and held-chord REC. Actual timing and
   long-session stability remain device-test requirements despite the rewrite.

Stop and return to the known-good update for hangs, stuck notes, audio
breakup or unrelated corruption. Please report the type, voice count, DUTY,
pitch and what DOOM/sample/effects activity was running.
