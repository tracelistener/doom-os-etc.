# DOOM/poly + Wave Lab v1 (experimental)

All 17 oscillator recipes from the local `sp404mk2-sound-generator/index.html`
Wave Lab are added **after** the stock list. Stock types 0–14, including Saw2,
are retained. This extends the DOOM/poly-v4 build the user reported working;
the new wave build is not yet hardware-tested or flashed automatically.

| Type | Name on SP | DUTY controls |
|---|---|---|
| 15 | FM1:1 | Modulation depth (7d²) |
| 16 | FM1:2 | Modulation depth (5d²) |
| 17 | FM1:7 | Modulation depth (2.5d²) |
| 18 | CZSaw | Phase-distortion brightness |
| 19 | CZSqr | Phase-distortion brightness |
| 20 | CZRes | Resonance ratio, 1–16 |

| 24 | LPSaw | Resonant harmonic-bank cutoff |
| 25 | LPSqr | Same, odd harmonics |
| 26 | Organ | Five interpolated registrations |
| 27 | Vowel | A/E/I/O/U interpolation |
| 28 | Table | Scan the original 32 frames |
| 29 | Logic | XOR ratio, 2–9 |
| 30 | Metal | Deterministic steps, 2–64 |
| 31 | Grit | Random-per-cycle pulse-width jump |

Names are shortened to fit the existing stock name buffer. DUTY remains
labelled Duty Cycle in the existing UI but acts as each new wave's timbre
control. The original waveform-picture getter safely returns no picture for
the new types; custom waveform drawings are not included.

Four voices, shared controls, held-pad lights, stop/reset and held-chord REC
remain in place. Normal sample pads and DOOM pattern tracks are not turned
into live synth pads by this addition.

## Implementation and sound differences

The recipes are compiled as freestanding Thumb-2 C, hardware floating point,
no allocation or mutable global state. Sine/cosine use a 2,048-point linearly
interpolated lookup table. The scanned table is the same 32 × 256 Float32
frame data generated by Wave Lab. Exponential math uses the stock exp2f
veneer. Grit reads the stock per-voice cycle random value at offset `0x40`.

The C module is 46,892 bytes. Bridges and padding make its appended copy
section 47,920 bytes at `0x8353e000`. It is loaded after zero-init through a
new 15th scatter row. The OS pool begins at `0x83549b4c`, with unchanged end
and alignment. Total reserved pool prefix is 63,552 bytes, 49,952 more than
poly-v4. Existing DOOM flash offsets and all unrelated bytes remain intact.

The new entry gateway retains the v4 export-call routing, stock oscillator
prologue, level scaling, phase advancement, envelope/fades and return path.
TYPE, FREQ, DUTY, name/text/label and export-period guards are extended.
The displaced stock name TBH is reconstructed from its original table;
stock names are tested too. New unknown type values still fall silent.

The browser demo additionally applies RMS matching, a DC blocker and output
saturation. The firmware deliberately uses Roland's existing LEVEL/envelope
chain instead. Fixed headroom multipliers are 0.16 for LPSaw/LPSqr/Organ and
0.46 for Vowel; other types use unity, with a final ±1 bound before stock
LEVEL scaling. Therefore preview loudness is not identical to the demo.
The existing polyphony half gain still applies. Four loud voices can clip.
Only the additive harmonic banks/organ impose their recipe's Nyquist guard;
nonlinear and table types can alias on high notes, as in the source recipes.

CPU headroom has **not** been measured. LP banks, Vowel and Drive are more
expensive than a stock simple waveform. Instruction tests do not establish
real-time safety under sample playback/effects/DOOM load.

## Reproduce and verify

Use the dependencies in `requirements.txt`, plus the pinned workspace-local
`ziglang==0.13.0` distribution (or an existing Zig 0.13.0 binary):

```sh
python -m pip install ziglang==0.13.0 --target .wave_toolchain
python synth/compile_waves.py --zig /path/to/zig
python synth/build.py /path/to/stock/SP404MKII_APP1.bin
python synth/patch_waves.py out/doom-poly-v4/SP404MKII_APP1.bin --out out/doom-poly-waves-v1 --web
```

If building from the fork directory, `.wave_toolchain` can be kept outside it
or is ignored by Git. On Windows the compiler is `.wave_toolchain/ziglang/zig.exe`.
The compile step generates ignored `build/waves/` lookup data, ELF, module,
symbols and source/tool provenance. The binary overlay in `waves-data.js`
is generated, not hand-edited. No complete Roland firmware is committed.

```powershell
$env:DOOM_STOCK_APP1 = 'C:\path\to\stock\SP404MKII_APP1.bin'
$env:DOOM_POLY_APP1 = 'C:\path\to\doom-poly-v4\SP404MKII_APP1.bin'
$env:WAVE_LAB_HTML = 'C:\path\to\sp404mk2-sound-generator\index.html'
python -m unittest discover -s synth -p 'test*.py'
node synth/test_browser.cjs $env:DOOM_STOCK_APP1
```

There are 83 integration tests: 40 previous composition/poly regressions and
43 on the wave image. The latter compare all 17 original JS formulas across
2,040 phase/DUTY/pitch cases (maximum absolute error <0.000012), run every new
type through the real oscillator, render four live voices, run held-chord
export through the real stock loop with simulated file I/O, check stock/new
labels and ranges, and execute real boot scatter copies for all added code.
The page/applier tests verify all three outputs, dependencies, reset, padded
base64 lengths and corrupt-overlay refusal. These are not full device boot,
visual browser, SD-card or timing tests. Original workspace tests also remain
passing and the working image is not overwritten.

## First hardware check

1. Verify backup and rollback files. Test boot and ordinary sample playback.
2. In Sound Generator, move TYPE past Noise2. The list should reach Grit.
3. Start with one voice at modest LEVEL. Sweep DUTY for FM1:1 and Fold, then
   try each remaining type. Duty 0 is intentionally a simple starting tone
   for some types, not silence.
4. Hold two, then four notes; check LEDs, shared DUTY, FREQ/TUNE and release.
5. Hold a chord while entering REC, then release and finish the normal
   destination workflow. Audition the rendered sample.
6. Check LP types/Vowel/Drive first at one voice, then increase voices while
   listening for crackles. Test DOOM/sample/effects load only after that.

Stop and return to the known-good update for hangs, stuck notes, audio
breakup or unrelated corruption. Please report the type, voice count, DUTY,
pitch and what DOOM/sample/effects activity was running.
