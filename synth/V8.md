# Wave Lab V8 RAM — raw grit restored

Current optional Wave Lab build in **our** [web patcher](https://tracelistener.github.io/doom-os-etc./).
All 17 added waves (TYPE 15–31) remain. The combined Sound Generator option stays OFF by default.
V8 is emulator-tested and has **not** been tested on the SP hardware.

## What changed

- Removed DUTY smoothing completely. Integer DUTY changes and small knob
  jitter apply immediately again, including the intentional at-rest crackle.
- Removed Sync/CZRes PolyBLEP. Their raw cycle-restart aliasing is back.
- Raw waveform math matches v3 in the tested FP32 cases. The *final* sound is
  not bit-identical to v3: v7's loudness/DC processing is retained.

Kept from v7: A-weighted loudness matching/DC removal for new waves; Pulse,
Noise1 and Noise2 6 dB quieter; source-aware note-off fallback after OCT
changes; FREQ display, ENV and START/END support; and the corrected release.
Wave code runs from SDRAM at `0x83f80000`, without further reducing the
poly-v4 OS pool. Static layout and emulator tests do not prove this region
is safe under every hardware workload or that real-time deadlines are met.

The other stock oscillator recipes, including Saw2, remain unchanged.
Four voices, shared controls, held-pad lights and held-chord REC remain.
This does not add live synth pads to normal sample playback or DOOM patterns.

## Use the web patcher

1. Back up samples/projects/settings. Keep stock 5.52 and your rollback pair.
2. Refresh our page and load **unmodified stock 5.52 APP1**. Select
   **Sound Generator (4 voices + 17 new waves)** to enable both together.
3. Download `SP404MKII_APP1.bin`. Pair it with the unchanged stock 5.52
   `SP404MKII_APP0.bin`. The page creates APP1 only; no firmware is uploaded
   and no device is flashed automatically.

APP1: **2,961,072 bytes**, SHA-256
`12dbeae4c85722e3109aa2359102e8525c0c5e3729fb64126456abd83ae283c7`.

APP0: **2,359,296 bytes**, SHA-256
`3e35ff30137f741a715566e205384f9b434ca7ac3847e247bad3f0c9c8a2bd23`.

Start with normal sample playback and one stock Sine at modest LEVEL. Then
check one new wave, release, OCT changes, FREQ/ENV/START-END, TYPE/DUTY sweeps,
two/four held voices, LEDs and chord REC. Raw DUTY crackle and Sync/CZRes
aliasing are deliberate; unexpected stock distortion, runaway loudness,
stuck notes or hangs are not. Stop and roll back for those problems. Save
simultaneous sampler/effects/DOOM load for last. CPU headroom is unmeasured.

For the smoother sound, use your saved `doom-poly-waves-v7-ram` pair. Turning
the Sound Generator option OFF produces upstream DOOM OS, **not v7 or poly-v4**.

## Reproduce from the fork

Python 3.12, the pinned `requirements.txt` dependencies and Zig **0.13.0**:

```sh
python -m pip install -r synth/requirements.txt
python synth/build_v8.py /path/to/stock/SP404MKII_APP1.bin --zig /path/to/zig --web
node synth/test_browser.cjs /path/to/stock/SP404MKII_APP1.bin
```

Stock APP0 must be beside APP1. The builder refuses to overwrite an existing
output directory; use a fresh `--out` for another run. It rebuilds the exact
module and full image from the copied v3–v8 pipeline helpers, using the frozen
v8 loudness table, then checks the reference module, symbol, layout and full
APP1 hashes before publishing `waves-data.js`. Outputs default to ignored
`out/doom-poly-waves-v8-ram/`. The web overlay round-trips from the original
poly-v4 image to the exact v8 image. Only overlay data/source are committed,
not complete Roland firmware, samples, projects or licenses.

The original helper scripts in `ram/waves_v3_ram` through `ram/waves_v8_ram`
retain their historical workspace defaults. Use the wrapper above, not those
scripts' old entry points. Public C/table source hashes use normalized LF;
the original CRLF digests are retained as provenance. Compiled image hashes
remain identical.

## Verification and limits

The original v8 harness passed all 13 checks, including 2,040 sampled raw
wave-math cases, representative DUTY-jitter spectra against v3/v7, immediate
DUTY response, Sync/CZRes aliasing, loudness, quieter stock Pulse/Noise,
OCT note-off, TYPE sweeps/four voices, startup copies, pool geometry and no
flash fetches in the exercised synth paths. Grit acceptance is within 3 dB
of v3 for ten representative waves; it is not an exhaustive spectral proof
for every pitch/DUTY/type combination. CPU estimates are optimistic weighted
instruction counts, not measurements on the device.

A portable copy of that harness is included. Supply your own reference images
and keep each reference image's `manifest.json` beside it:

```sh
python synth/ram/waves_v8_ram/check_v8.py --stock /path/to/stock/APP1.bin --v8 /path/to/v8/APP1.bin --v7 /path/to/v7/APP1.bin --v3 /path/to/v3-ram/APP1.bin --base /path/to/poly-v4-releasefix/APP1.bin
```

The browser test also checks exact v8 hash/size, revision and metadata,
single-option opt-in/reset behavior, unchanged upstream/poly-only overlay outputs and
corrupt-overlay rejection. Six additional publication tests verify source
guards, the exact overlay/output, pool/scatter layout and one raw sample for
every TYPE 15–31 / integer DUTY 0–100 pair (1,717 guaranteed combinations):

```powershell
$env:DOOM_STOCK_APP1 = 'C:\path\to\stock\SP404MKII_APP1.bin'
$env:DOOM_V8_APP1 = 'C:\path\to\v8\SP404MKII_APP1.bin'
$env:DOOM_V3_RAM_APP1 = 'C:\path\to\v3-ram\SP404MKII_APP1.bin'
python -m unittest discover -s synth -p test_v8.py -v
```

This still samples phase/pitch/random inputs rather than proving equivalence
over all possible states. No test here models the RTOS, actual peripherals,
cache/bus stalls, SD update process or full hardware timing/stability.
