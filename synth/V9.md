# Sound Generator v9.5 RAM

**Archived v9.5 notes.** The current patcher ships [v9.6](SCALES.md): the same
waves/envelopes/stealing plus 34 scale choices and FREQ/pad note-off fixes.
Use the v9.6 output hash and publication instructions there, not this page's
v9.5 output hash, when checking a current browser download.

The [web patcher](https://tracelistener.github.io/doom-os-etc./) has one optional
Sound Generator choice, OFF by default. It combines DOOM OS 0.6.1 ED5E with
four-voice polyphony, all 17 added waves, envelopes, voice stealing, scale
pads and four-voice MIDI IN.

**Status (2026-10-07):** v9.5 passes all 32 emulator checks; hardware
confirmation is pending. It addresses a click found in the v9.4 hardware test.
The earlier build v9.1 was reported as **“hardware test is good” on
2026-10-07** (coverage not specified). CPU headroom and long-session stability
remain unmeasured. To rebuild an earlier build, see [Previous builds](#previous-builds).

## Changes

### v9.5

- Reduced click when a new note has to take a busy voice, e.g. letting go of one
  note of a four-note chord and playing another while the first still rings
  out. The busy voice used to be cut short in place: its waveform stopped dead
  and its last sample decayed under the new note as a thump. Now it fades out
  over 2.8 ms (the stock release fade at triple speed), and the new note then
  starts cleanly on it, about 3 ms later. The stock note-on waits in the same
  way when you retrigger a note that is still releasing. MIDI IN steals the same way.

### v9.4

- Scale pads: with SCALE set to anything other than Chrom, the 16 pads play
  only scale notes, one scale step apart, so one bank spans two octaves and a
  step (7-note scales) or three octaves (pentatonic). See [Scale pads](#scale-pads).
- MIDI IN plays all four voices (it played one), with the same voice
  stealing as the pads. A held MIDI note lights the pad with the same pitch.
- Pressing REC while holding notes fades them out (about 9 ms) instead of
  cutting them, so there is no click. The held chord is still recorded.
- Every recording made with an ENV preset fades out at its end. ENV OFF with
  Pad Length in periods and START/END on (the default) still ends on a whole
  waveform cycle, so raw-wave loops stay seamless.

### v9.2 and v9.3

- Recordings no longer end with a hard cut: they fade out over their last
  10 ms (the last quarter on very short pads).
- The FREQ readout follows the latest note instead of voice 0, which long
  releases often keep busy. The FREQ knob steps from the note on the screen and
  still moves every held note by the same interval. Pitch itself was measured
  exact; only the readout was stale.

### v9 and v9.1

- ENV: OFF, Pluck, Perc, Keys, Pad, Swell, Bass, Acid, Sweep and FPad. Five
  volume-envelope presets and four volume/filter-envelope presets replace the
  nine original non-OFF shapes. OFF preserves the stock envelope behavior.
- Bass, Acid, Sweep and FPad use a custom resonant low-pass with an envelope.
  This is our implementation, not a recovered Roland/ZEN-Core engine.
- A fifth note steals the oldest fading voice, otherwise the oldest held
  voice, with a roughly 2 ms de-click decay. Later note-offs for stolen notes
  are ignored.
- v9.1 fixes silent REC export of inactive voices and stale selected TYPE/UI
  state. REC still renders a static held chord, not a live performance.
- All v8 wave recipes and raw DUTY/Sync/CZRes grit remain unchanged. V7's
  loudness, release, OCT note-off, FREQ/ENV/START-END and safe RAM placement
  fixes remain. Stock types, including Saw2, are retained.

Normal sample pads and patterns are not converted into live synth pads.
Four loud voices can still clip: begin at a modest LEVEL. Back up your
samples, projects and settings and retain a known-good firmware pair.

## Using ENV

Choose a preset with the existing **ENV** control in Sound Generator, then
play a new note. A voice latches its preset at note start; changing ENV does
not replace the envelope of an already sounding voice. The preset setting is
shared, but each of the four voices has its own envelope/filter history.

Pluck and Perc decay to silence even while held (Perc is longer). Keys decays
to a quieter held level. Pad and Swell fade in and sustain until release;
Swell is slower. Bass and Acid close a resonant filter after a fast attack;
Acid uses stronger resonance/drive and a shorter release. Sweep has a quick
volume attack with a slowly opening filter. FPad combines a soft volume
attack with slow filter movement and a long release.

The filter cutoff follows note pitch and its own envelope. ENV selects fixed
presets, not individually editable ADSR/cutoff/resonance parameters. Releasing
a note lets its volume/filter release run; all-stop still ends the sound with
the stock short fade. REC renders the selected preset on the held chord using
separate export-voice state. OFF keeps stock behavior.

## Scale pads

Stock Sound Generator pads are 16 semitones around pad 9, and a SCALE only
darkens and mutes the pads outside it. Since v9.4, with any SCALE other than Chrom:

- pad 9 plays the first scale note at or above the note it plays in Chrom;
- the pads keep their order, from the bottom row (lowest) to the top row
  (highest), left to right, each one scale step above the one before;
- a bank spans 26 semitones with a 7-note scale and 36 with a pentatonic one,
  and every pad plays;
- the pad lights keep their stock meaning (root pads, notes below and above
  the root), and notes outside the stock range stay dark and silent;
- NOTE, OCT and the keyboard shift work as before.

Chrom is unchanged. The new layout applies only on the Sound Generator page.
Elsewhere, the shared keyboard settings and pad lights behave exactly as in v9.3.

## MIDI IN

On the Sound Generator page, notes from an external MIDI keyboard now use all
four voices. The stock route played voice 0 only. A fifth key steals like a
fifth pad: the oldest fading voice, else the oldest held one. A note-off
releases only its own key, a stolen key's note-off does nothing, and pads and
MIDI notes never release each other. MIDI routing itself is stock.

## What the checks establish

v9.5 passes all 32 checks of the emulator suite (real firmware code in
Unicorn, with no RTOS, peripherals or timing). The v9–v9.3 checks still pass:
ENV OFF is bit-identical to v8, plus preset timings, filter sweeps, all-stop,
stealing, REC through the real stock exporter and the FREQ readout. While a
note-on waits for a stolen voice, the harness lets the audio task run, as the
SP does.

v9.5 adds:

- **Reduced stealing clicks in the tested chords.** On a sine chord, letting go of one note and playing
  another 8 ms later used to put −38 dB (Pad) and −33 dB (Keys) of energy
  above 2.5 kHz into the mix. It now puts −60 and −51 dB. A plain ENV OFF note
  start is −28 dB. A fifth note takes the oldest voice after a 3 ms fade-out.
- **Fallback.** If the fade cannot finish (no audio for 30 ms), the steal still
  happens, in place.

v9.4 added (31 checks then):

- **Scale pads:** 672 pad cases through the real note-on/note-off code and the
  pad-light helpers. On the Sound Generator page they match a model of the
  scale walk. In Chrom and on other pages they match v9.3 run on the same code,
  including which out-of-scale pads are skipped.
- **MIDI IN through the real dispatcher:** four keys take four voices and a
  fifth steals the oldest. Note-offs release only their own key, and pads and
  MIDI never release each other.
- **REC entry:** a held chord fades to silence in about 9 ms, where v9.3 cut it
  at once, and is still captured.
- **Periods-mode REC through the real exporter:** a Pad recording ends at
  zero, and an ENV OFF loop is byte-identical to v9.1.

The v9.1 REC audit is still valid for v9.1 but was not rerun on v9.4 or v9.5. It
covered eight arithmetic-oracle tests and ten byte-exact stereo/mono export
cases. It found that the native export path writes big-endian PCM, which the
older test had decoded as little-endian. These tests establish the tested
behavior, not complete engine equivalence or real-time CPU margins.

The public source rebuilds byte-for-byte to the image below. Browser
regression tests check exact plain-DOOM and v9.5 downloads, opt-in/reset
behavior, hash rejection and corrupt overlays.

## Reproduce from source

Use Python with [the pinned dependencies](requirements.txt) and **Zig 0.13.0**:

```sh
python -m pip install -r synth/requirements.txt
python synth/build_v9.py /path/to/stock/SP404MKII_APP1.bin --zig /path/to/zig
# Add --web to regenerate waves-data.js after all exact-output guards pass.
```

Stock APP0 must be beside APP1. Outputs default to ignored
`out/doom-poly-waves-v9.5-ram/`; existing output directories are never
overwritten (choose a fresh `--out` path). The builder compiles freestanding
ARM code, checks source/module/layout/output hashes and reuses the frozen
v8 wave tables. It does not execute a native host DLL or flash a device.
Use this wrapper, not the archived helper `ram/waves_v9_ram/build_v9.py`.
The helper's manifest is the build-time record; the wrapper adds the
current hardware status to the publication metadata.

```powershell
$env:DOOM_STOCK_APP1 = 'C:\path\to\stock\SP404MKII_APP1.bin'
$env:DOOM_V9_APP1 = 'C:\path\to\out\doom-poly-waves-v9.5-ram\SP404MKII_APP1.bin'
python -m unittest discover -s synth -p test_v9.py -v
node synth/test_browser.cjs $env:DOOM_STOCK_APP1
```
